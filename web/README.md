# formation-chess-web

`formation-chess-web` is the local browser client for
[Formation Chess (阵棋)](../README.md). Axum serves embedded HTML, CSS,
JavaScript, and the synchronized Chinese rule text; no frontend build step is
required.

The server binds to `127.0.0.1` and keeps one in-memory game session. Red and
Black each own an independent Min Agent instance. Either side may be Human- or
Agent-controlled, and each Agent side independently selects very-weak, weak, or
medium strength. The default is Red Human and Black medium Agent. Restarting the
process starts a fresh session.

## Run from the workspace

```sh
cargo run -p formation-chess-web
```

Without an argument, the server asks the operating system for an available port,
prints the URL, and attempts to open the default browser. To request a port:

```sh
cargo run -p formation-chess-web -- 4000
```

Refreshing the browser reloads the current state with `GET /api/state`. There is
no authentication, remote matchmaking, or durable game storage.

## UI behavior

- Red and Black independently select Human control or very-weak, weak, or medium Min AI strength.
- Human turns can request up to five ranked Min hints.
- Mixed Human/AI games automatically play one AI reply after a human action.
- AI-vs-AI games advance only when the user clicks `下一步`.
- Standard and custom boards support dimensions from 1×1 through 16×16.
- Random placement is generated by the backend and replaces the session only
  after the complete layout is ready.
- Complete text snapshots can be loaded through the custom-game panel.
- Selecting a controlled piece shows its complete core legal-action menu,
  including move, capture, push, pull, draw, and targeted resign candidates.
- The board renders both Red's down-pointing Mobility pentagon and Black's
  vertically mirrored up-pointing pentagon.
- A successful draw updates both exchanged pieces with Leader.
- The standalone resign button is shown only during placement. During movement,
  resignation is the `认负` candidate on a controlled General's action menu.
- Undo restores one action in Human/Human or Agent/Agent games. In mixed games,
  it restores the position before the latest human action and automatic AI
  reply.

Creating or loading a new game clears the undo history.

## HTTP API

Coordinates are 0-based `[x, y]` pairs. Every state-changing or analysis
request carries the current `revision` and `side`; stale or wrong-side requests
are rejected.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | Serve the embedded Web UI |
| `GET` | `/api/state` | Return the current session state |
| `POST` | `/api/action` | Submit one action for the current Human side |
| `POST` | `/api/agent/analyze` | Return up to `top_k` ranked Agent candidates |
| `POST` | `/api/agent/step` | Execute the current Agent side's top candidate |
| `POST` | `/api/new` | Create or notation-load a game |
| `POST` | `/api/undo` | Undo one action or one mixed-controller round |
| `GET` | `/api/rules` | Return the embedded Chinese rules text |

### State and piece identity

The current controller is explicit even when both Agent instances have the same
display name:

```json
{
  "revision": 17,
  "player": "Red",
  "phase": "movement",
  "controllers": {
    "red": { "control": "agent", "strength": "very_weak", "agent": "Min AI web-very-weak-v1" },
    "black": { "control": "agent", "strength": "weak", "agent": "Min AI web-weak-v1" }
  },
  "current_controller": {
    "side": "Red",
    "control": "agent",
    "strength": "very_weak",
    "agent": "Min AI web-very-weak-v1"
  }
}
```

Board and pool pieces identify their owner with the `player` field:

```json
{ "name": "风", "player": "Red", "formation": 90 }
```

`formation` is the core formation bit pattern. The frontend recognizes both
pentagon orientations (`93` down and `186` up), as well as the mirrored triangle
patterns.

Board and pool pieces also carry `formation_effect`, two strings describing what
the piece's formation grants (`赋予`) or strips (`剥夺`) from `allies` and
`enemies`, using the official Chinese ability names:

```json
{ "formation_effect": { "allies": "赋予 拉友、拉敌", "enemies": "剥夺 拉友、拉敌" } }
```

### Human actions

All actions use a tagged `type` field:

```json
{
  "revision": 17,
  "side": "Red",
  "action": { "type": "move", "from": [4, 9], "to": [4, 8] }
}
```

Movement interactions use the same `from`/`to` shape:

```json
{ "type": "capture", "from": [1, 2], "to": [2, 2] }
{ "type": "push", "from": [1, 2], "to": [2, 2] }
{ "type": "pull", "from": [2, 2], "to": [3, 2] }
{ "type": "draw", "from": [4, 8], "to": [4, 1] }
```

Placement and targeted resignation are:

```json
{ "type": "place", "piece": { "name": "风", "player": "Red" }, "to": [4, 9] }
{ "type": "resign", "at": [4, 9] }
```

During placement the backend ignores the resign coordinate; the UI sends
`[0, 0]`. During movement, `at` must identify the controlled piece with Leader that
is resigning.

### Legal actions and Agent analysis

Every state response includes `legal_actions`, containing all legal movement
`ApiAction` values for the current position and player. The list is empty during
placement and after the game finishes. For a controlled General, it may include
`{ "type": "resign", "at": [4, 9] }` in addition to movement interactions.
The Web UI filters this list by `from` or `at` when a board piece is selected.

Agent analysis uses:

```json
{ "revision": 17, "side": "Red", "top_k": 5 }
```

Candidates are ordered best-first. Every candidate contains the complete action,
its game-aware notation, and a finite score. Array order is the rank. The step
endpoint has no `top_k` field and executes Min's top-one candidate.

### New games and random placement

```json
{
  "revision": 17,
  "side": "Red",
  "controllers": {
    "red": { "control": "human", "strength": "medium" },
    "black": { "control": "agent", "strength": "weak" }
  },
  "board": { "width": 9, "height": 10 },
  "random_placement": true
}
```

Each controller also accepts the legacy string form (`"human"` or `"agent"`),
which defaults to medium strength. The Web UI sends the structured form so the
two Agent sides can use different strengths. Strength primarily scales search
node budgets: very-weak uses 1,500 placement / 90 movement nodes, weak uses
3,000 / 450, and medium uses 6,000 / 750. Search widths are also narrowed.
All three profiles use two-ply movement search; very-weak additionally uses a more
material-oriented evaluation. These remain approximate responsiveness targets
rather than hard wall-clock deadlines.

When `random_placement` is true, the backend alternates the two configured Min
agents until placement is complete, then atomically replaces the session with
the resulting movement-phase game. Independent score-Softmax selectors sample
only close layout candidates and keep clear best moves deterministic; normal
Agent steps remain deterministic top-one play. Intermediate placements are not
returned.
